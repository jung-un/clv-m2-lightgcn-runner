# M3 historical-CLV 가중 다음 신규상품 전이그래프 설계

## 1. 지위와 연구질문

이 방법은 여러 M3 음의 결과를 본 뒤 정의한 사후·탐색적 후보다. 이전
결과를 소급해 확증적 방법으로 서술하지 않는다.

연구질문은 다음과 같다.

> 학습구간 historical CLV가 높은 고객에게서 관찰된 `현재 상품 → 다음
> 장바구니의 첫 구매 상품` 전이를 item–item 관계로 더 크게 반영하면,
> CLV를 쓰지 않은 같은 전이그래프보다 신규상품 추천이 개선되는가?

핵심은 CLV에 상품 식별을 직접 맡기지 않는 것이다.

- historical CLV: 누구의 전이 경험을 더 크게 반영할지 결정
- 상품 전이: 어떤 기존 상품에서 어떤 신규상품으로 이동하는지 표현
- 개별 사용자 이력: 어느 전이경로를 실제로 사용할지 결정

## 2. 불변 조건

- 평가 과업은 신규상품 추천이다. 평가 시점 이전에 구매한 `(user,item)`
  쌍은 정답과 추천 후보에서 제외한다.
- `MIN_USER_INTER=1`, `MIN_ITEM_INTER=1`로 전체 카탈로그를 보존한다.
- M1의 binary user–item 엣지집합과 LightGCN 정규화는 변경하지 않는다.
- 상품 가격·구매금액을 전이엣지 입력으로 쓰지 않는다.
- N/V를 분리해 사용자 유형별로 다른 규칙을 적용하지 않는다. 전체
  `historical CLV proxy = N_hat * V_hat`를 하나의 계수로 사용한다.
- 최종 모형을 학습할 때는 동결·후처리 재정렬 없이 하나의 BPR 손실과
  하나의 optimizer로 user–item·item–item 경로를 공동학습한다.
- 이미 확인한 최종 test·holdout은 구성하지 않는다.

## 3. 1단계: 모형 학습 전 train-only 전이관계 타당성 진단

첫 구현은 GPU LightGCN 학습이 아니라 전이관계 자체의 식별력 진단으로
한정한다. 이 단계를 통과하지 못하면 모형을 구현하지 않는다.

### 3.1 시간구간

- 전이 구성: Dunnhumby `DAY 1~662`
- 가상 미래 평가: `DAY 663~669`
- `DAY 670` 이후, 기존 historical validation/test, 최종 test·holdout은 읽지
  않는다.

이 구간은 확증용이 아니라 사후 탐색후보의 train-only 내부 타당성 진단이다.
신뢰구간·유의성·일반화를 주장하지 않는다.

### 3.2 다음 신규상품 전이 사건

사용자 `u`의 연속 장바구니 `B_(u,t)`, `B_(u,t+1)`에서 도착 상품을
다음과 같이 정의한다.

```
New_(u,t+1) = B_(u,t+1) - History_(u,t)
```

`History_(u,t)`는 `t`까지 한 번이라도 구매한 모든 상품이다. `New_(u,t+1)`이
빈 장바구니 쌍은 전이사건에서 제외한다. 시간 한계 하이퍼파라미터를
추가하지 않고 직전 다음 장바구니만 연결한다.

장바구니 크기를 보정한 전이 기여는 다음과 같다.

```
x_(u,i,j,t) = 1[i in B_(u,t), j in New_(u,t+1)]
              / (|B_(u,t)| * |New_(u,t+1)|)
```

사용자별 전이 기여량을 다시 합계 1로 정규화한다.

```
xbar_(u,i,j) = sum_t x_(u,i,j,t) / sum_(a,b,t) x_(u,a,b,t)
```

이로써 큰 장바구니·많은 전이횟수가 자동으로 한 사용자의 그래프
총기여량을 키우지 못하게 한다.

### 3.3 historical CLV 계수

구성구간에서 사용자별로 다음을 계산한다.

```
N_hat_u = number of distinct baskets
V_hat_u = mean basket value
CLV_u   = N_hat_u * V_hat_u
```

데이터셋 금액척도와 관찰기간 차이를 줄이기 위해 사용자 중간순위 백분위
`q_u`를 사용하고 평균 1 계수로 변환한다.

```
c_u = (0.5 + q_u) / mean_v(0.5 + q_v)
```

고객별 N/V 조건분기나 재학습되는 CLV encoder는 없다.

### 3.4 세 전이그래프

같은 전이사건에 대해 다음 세 그래프를 만든다.

```
T_global(i,j) = sum_u xbar_(u,i,j)
T_clv(i,j)    = sum_u c_u * xbar_(u,i,j)
T_shuffle(i,j)= sum_u c_perm(u) * xbar_(u,i,j)
```

`c_perm(u)`는 활동량 대조를 위해 `N_hat`의 중간순위 10분위 내에서 고정 seed
`20260826`로 `c_u`를 순열한 값이다. 이로써 단순 활동량은 유지하고 올바른
CLV 배정만 깨뜨린다.

상품 인기도가 모든 전이를 지배하지 않도록 그래프별로 source item `i`
내 행합 1로 정규화한다. 현재 단계에서는 PPMI·최소관찰횟수·top-M을
적용하지 않고, 지원도 분포를 진단결과로 저장한다. 결과를 본 뒤 임계값을
선택하는 것을 막기 위함이다.

### 3.5 가상 미래 추천점수

가상 미래 정답은 `DAY 663~669` 전체에서 구성구간 이전에 구매하지 않은
상품의 고유집합으로 두어 기존 7일 신규상품 평가와 같게 만든다.

평가 사용자의 구성구간 마지막 장바구니 상품 `H_last(u)`에서 도착 상품
점수를 합산한다.

```
score_g(u,j) = sum_(i in H_last(u)) T_g(i,j) / |H_last(u)|
```

구성구간에 사용자가 이미 구매한 상품은 후보에서 제외한다. 그래프에서
도달할 수 없는 상품에 인기도 점수를 보충하지 않는다. 이는 전이관계 자체의
coverage와 순위력을 분리해 보기 위함이다.

### 3.6 진단지표

- Recall/NDCG @10·20·50: 가상 미래의 신규상품 정답으로 계산
- reachable-truth share: 정답이 전이그래프에서 양수 점수로 도달 가능한 비율
- 사용자별 양수 후보 수 분포
- 상품별 고유 전이사용자 수별 Recall/NDCG
- 전이점수–도착상품 인기도 Spearman 상관
- 전이점수–도착상품 가격백분위 Spearman 상관
- Top-10 추천 고유상품 수, 노출 엔트로피, 실효 카탈로그, 상위 10개
  상품 노출점유율
- 저·중·고CLV 사용자별 같은 지표

### 3.7 1단계 사전 판정

`T_clv`가 다음을 모두 만족할 때만 2단계 LightGCN 모형 구현을 연다.

1. Recall/NDCG @10·20·50가 각각 `T_global`의 99% 이상
2. Recall@10과 NDCG@10이 `T_global`보다 모두 크거나, 둘 중 하나가 크고
   다른 하나는 같음
3. Recall@10과 NDCG@10이 `T_shuffle`보다 모두 크거나 같음이며, 적어도
   하나는 엄격히 큼
4. reachable-truth share가 `T_global`의 99% 이상
5. Top-10 고유상품 수가 `T_global`의 95% 이상
6. Top-10 상위 10개 상품 노출점유율 증가가 `1%p` 이하

가격·구매금액 가중 적중값은 1단계 선택조건으로 쓰지 않는다. 이 단계의
질문은 전이관계가 신규상품 정답을 구분하는지이며, 가격 성과로 우회하지
않는다.

## 4. 2단계: 조건부 LightGCN 파일럿

1단계가 양성일 때만 상세 구현계획을 작성한다. 현재 고정하는 경계는
다음과 같다.

- 모형 arm: `M1`, `M1 + T_global`, `M1 + T_clv`
- `T_clv`가 첫 파읿럿에서 두 대조군을 넘으면 같은 모형에 `T_shuffle`을 추가
- user←item M1 전파는 변경하지 않음
- item←user M1 전파는 변경하지 않음
- item←item 전이메시지를 별도로 정규화해 추가
- 관계별 학습형 계수는 1차 모형에서 사용하지 않음
- 외부 점수합산·재정렬이 아니라 같은 LightGCN layer와 BPR 손실로 공동학습

2단계 새 평가구간은 `DAY 1~669` 학습, `DAY 670~676` 신규상품 평가로
사전 고정한다. 1단계 가상미래와 다른 구간이다. 단, 이 또한 사후 탐색후보의
역사적 개발 파일럿이며 최종 확증으로 사용하지 않는다.

## 5. 대안과 기각 이유

### 대안 A: CLV profile–item 관계를 support 임계로 수정

기존 PPMI 관계에 최소구매자 수를 추가하는 것은 구현이 쉽다. 하지만 같은 CLV
구간의 모든 사용자가 같은 메시지를 받는 평탄화 문제가 남고, 임계값을 기존
평가결과에 맞추는 사후 탐색 위험이 크다.

### 대안 B: CLV profile–item 학습형 attention

개별 사용자 이력으로 profile 상품을 attention하면 평탄화를 줄일 수 있다.
그러나 추가 파라미터가 CLV 정보 없이도 성능에 맞는 자유도를 제공하며,
교수님의 성능 맞춤형 구조·일반화 우려를 다시 받을 가능성이 크다.

### 대안 C: V-contribution을 최종 M3로 사용

V-contribution은 가장 유망한 축별 결과지만 전체 historical CLV를 사용한 모형이
아니다. 전이관계가 실패하면 V-only를 CLV 제안기법으로 과장하지 않고,
M3 전체는 음의 결과, V-only는 구성요소 ablation으로 보고하는 것이 맞다.

## 6. 오류처리와 품질검사

- 사용자의 유효 전이사건이 없으면 진단평가에서 제외하고 제외 수를
  보고한다.
- source·target item index가 학습 카탈로그 범위를 벗어나면 실행을 중단한다.
- 모든 전이엣지는 구성구간 내 연속 장바구니만 사용하고 가상미래 행을
  참조하지 않는다.
- CLV·백분위·N 구간·shuffle은 모두 구성구간에서만 계산한다.
- 유효 전이가 있는 사용자의 전이기여량 합계는 `1`, 양의 출발엣지가 있는
  상품의 전이그래프 행합도 `1`인지 검사한다. 출발엣지가 없는 상품의
  행합은 `0`으로 허용한다.
- 가상미래 정답과 추천에 구성구간 구매쌍이 있으면 품질검사를 실패처리한다.
- 재계산한 Recall/NDCG와 저장지표가 `1e-8` 이내로 일치해야 한다.
- 설정·입력 manifest·소스 revision·고정 shuffle seed를 결과 JSON에 저장한다.

## 7. 선택하지 않은 사항

- 결과를 본 뒤 전이 시간간격·CLV 구간 수·support 임계·top-M·온도를 조정하지
  않는다.
- 정답 상품 색인을 전이그래프 구성에 사용하지 않는다.
- 가격·구매금액 입력을 전이관계에 추가하지 않는다.
- 저·중·고CLV별 다른 규칙을 적용하지 않는다.
- 1단계가 음성인데 LightGCN 결과를 보기 위해 2단계를 실행하지 않는다.
