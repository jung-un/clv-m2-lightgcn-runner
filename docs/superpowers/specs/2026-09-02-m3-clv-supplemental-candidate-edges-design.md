# M3 일반 관계 밖 CLV 추가 후보 엣지 설계

## 1. 연구축과 마지막 가설

이 설계는 M1~M5 중 **M3 그래프 구조·전파 개입**에 해당한다. M1의 이진
사용자–상품 구매 그래프는 유지하고, 학습기간에 아직 구매하지 않은 상품을
향하는 별도의 사용자–상품 관계를 추천모형 내부에 추가한다.

검정할 질문은 다음과 같다.

> 전체 고객의 일반 신규상품 관계를 보존한 상태에서, 학습기간 구매횟수와
> 평균 거래금액의 곱으로 정의한 historical CLV proxy가 일반 관계 밖에서
> 추가 신규상품 후보를 더 정확하게 선택하는가?

이 질문은 기존 엣지의 세기나 공통 후보의 순서를 CLV로 다시 조절하는 이전
M3와 다르다. CLV는 일반 관계가 놓친 후보의 **존재 여부**에만 개입한다.

## 2. 이 설계를 선택한 근거

기존 양의 단서는 DAY 1~683 학습, DAY 684~690 평가의 사후 진단에서
나왔다.

- CLV 조건부 후보: 정답 310개 포함
- degree-matched CLV shuffle 후보: 정답 284개 포함
- CLV와 무관한 일반 후보: 정답 562개 포함

따라서 정상 CLV 배정은 shuffle보다 26개의 정답을 더 포함했지만, CLV
후보로 일반 후보를 대체하면 일반 후보가 포함하던 정답을 크게 잃었다. 반면
DAY 1~690 학습, DAY 691~697 평가의 공통후보 실험에서는 actual과 shuffle의
Recall@10·20·50 및 가격·구매금액 가중 적중값이 같았다. 동일 후보 안의
재가중만으로는 CLV 고유 효과를 확인하지 못했다.

이에 따라 일반 후보를 없애거나 재정렬하지 않고, CLV가 고른 소수 후보만
일반 후보 밖에 추가한다. 위 수치는 이미 본 구간의 기술적 근거일 뿐이며,
새 모형의 성능 증거로 재사용하지 않는다.

## 3. 학습기간 입력

사용자 `u`의 historical CLV proxy는 기존 연구 정의를 유지한다.

\[
C_u^{hist}=\widehat N_u\widehat V_u
\]

- \(\widehat N_u\): 학습기간의 고유 basket 수
- \(\widehat V_u\): 학습기간 basket당 평균 구매금액
- \(q_u\): 학습 사용자 안에서 \(C_u^{hist}\)의 mid-rank 백분위

모든 값은 train-only로 계산한다. 미래 CLV나 추천 이후의 가치 증가는
뜻하지 않는다. 상품 가격은 관계 추정 입력으로 사용하지 않는다.

사용자 자신의 통계가 자신의 후보관계 추정치에 직접 섞이지 않도록 기존과
같은 5-fold 사용자 cross-fitting을 유지한다. 카테고리·상품 확률의 축소강도
`kappa=20`, 최소 사용자 지지도 `5`도 바꾸지 않는다.

## 4. 일반 관계와 CLV 조건부 관계

사용자의 최근 구매 카테고리 비중을 \(r_{uc}\)라 한다. 기존 구현과 같은
train-only 최초 상품 획득 통계로 다음 두 관계점수를 계산한다.

### 4.1 일반 관계

\[
G_{ui}=\sum_c r_{uc}\sum_d
P_0(d\mid c)P_0(i\mid d)
\]

여기서 \(P_0(d\mid c)\)는 CLV와 무관한 pooled 카테고리 전이확률이고,
\(P_0(i\mid d)\)는 카테고리 `d` 안에서 상품 `i`가 처음 획득된 pooled
확률이다.

### 4.2 CLV 조건부 관계

\[
P_q(d\mid c,u)=(1-q_u)P_L(d\mid c)+q_uP_H(d\mid c)
\]

\[
P_q(i\mid d,u)=(1-q_u)P_L(i\mid d)+q_uP_H(i\mid d)
\]

\[
C_{ui}(q_u)=\sum_c r_{uc}\sum_d
P_q(d\mid c,u)P_q(i\mid d,u)
\]

CLV가 일반 관계를 넘어 추가로 설명하는 양의 초과분은 다음과 같다.

\[
\Delta_{ui}(q_u)=[C_{ui}(q_u)-G_{ui}]_+
\]

학습기간에 이미 구매한 `(u,i)`는 모든 후보에서 제외한다.

## 5. 후보집합과 관계 질량

하이퍼파라미터는 이전 실행 범위 안에서 다음 한 점으로 고정한다.

- 일반 기본 후보 수 \(K=100\)
- 추가 후보 수 \(m=20\)
- 일반 블록 질량 \(K/(K+m)=5/6\)
- 추가 블록 질량 \(m/(K+m)=1/6\)

### 5.1 모든 arm이 공유하는 기본 후보

\[
S_u^G=\operatorname{Top100}_{i}G_{ui}
\]

기본 블록의 가중치는 `S_G` 안에서만 정규화한다.

\[
\bar G_{ui}=\frac{G_{ui}}{\sum_{j\in S_u^G}G_{uj}}
\]

### 5.2 각 arm의 추가 후보

일반 관계 대조군은 pooled 관계의 101~120위 상품을 사용한다.

\[
E_u^{general}=\operatorname{Rank}_{101:120}G_{ui}
\]

실제 CLV와 shuffle은 `S_G` 밖의 양의 초과분 상위 20개를 사용한다.

\[
E_u^{actual}=\operatorname{Top20}_{i\notin S_u^G}\Delta_{ui}(q_u)
\]

\[
E_u^{shuffle}=\operatorname{Top20}_{i\notin S_u^G}
\Delta_{ui}(q_u^{shuffle})
\]

`q_shuffle`은 사용자 degree 구간 안에서 historical CLV 백분위를 순열해
만든다. 실제 CLV와 shuffle은 같은 사용자별 후보 수와 질량을 갖는다.

각 arm의 최종 보조 관계는 다음과 같다.

\[
B_{ui}^{a}=\frac56\bar G_{ui}\mathbf 1(i\in S_u^G)
+\frac16\frac1{20}\mathbf 1(i\in E_u^a)
\]

따라서 모든 활성 사용자에 대해 다음이 정확히 성립해야 한다.

- 후보 엣지 수: 120개
- 기본 후보 엣지와 기본 블록 가중치: arm 간 동일
- 추가 블록 총질량: `1/6`
- 전체 행질량: `1`
- actual과 shuffle의 유일한 차이: 추가된 20개 상품의 정체성

추가 블록에서 raw 초과확률 크기를 다시 가중치로 사용하지 않는다. 이번
검정의 대상은 이전 진단에서 양의 단서가 나온 **후보 선택**이기 때문이다.
강도와 후보 정체성을 동시에 바꾸면 CLV 귀속을 분리할 수 없다.

사용자에게 양의 초과분 후보가 20개 미만이면 pooled 후보로 몰래 채우지
않고 실행 전 오류로 중단한다. 이 조건을 통과한 경우에만 세 arm의 비교가
성립한다.

## 6. LightGCN 내부 적용

M1의 이진 구매그래프와 2층 LightGCN 표현을 그대로 계산한다.

\[
(z_u^{M1},z_i^{M1})=LightGCN(A_{binary})
\]

보조 관계의 상품 메시지를 같은 forward graph 안에서 더한다.

\[
m_u^a=\sum_iB_{ui}^az_i^{M1}
\]

\[
z_u^a=z_u^{M1}+0.075m_u^a,
\qquad S^a(u,i)=(z_u^a)^\top z_i^{M1}
\]

상품 ID 임베딩과 사용자 ID 임베딩은 하나의 plain BPR 손실, 하나의
optimizer, 하나의 학습루프에서 함께 갱신한다. 보조 관계를 외부 재정렬에
사용하지 않는다.

## 7. 비교 arm

1. `m1_baseline`: 이진 구매그래프만 사용
2. `m3_general_candidate_item_relation_control`: 일반 기본 100개 + pooled
   101~120위 추가 블록
3. `m3_clv_conditioned_supplemental_candidate_item_relation`: 일반 기본
   100개 + 실제 CLV 초과분 20개
4. `m3_clv_conditioned_supplemental_candidate_item_relation_shuffle`: 일반
   기본 100개 + degree-matched shuffled CLV 초과분 20개

arm 2~4는 동일한 초기화, 미니배치 순서, uniform 음성표본을 사용한다.
차이는 보조 그래프의 추가 20개 상품뿐이다.

## 8. 변경하지 않는 학습 조건

- 신규상품 추천: train의 `(user,item)`은 평가 정답과 추천 후보에서 제외
- `MIN_ITEM_INTER=1`
- M1 이진 구매그래프 보존
- ID 임베딩 64차원, LightGCN 2층, 0·1·2층 단순평균
- uniform negative sampling
- 표본가중치 없음
- plain BPR 하나, 추가 손실 없음
- `gamma=0.075`
- 100 epoch 고정, epoch 선택 없음
- 한 모델당 하나의 optimizer와 학습루프
- 상품 가격 입력 없음
- 외부 재정렬 없음
- 최종 평가는 test로 종료하고 holdout은 만들지 않음

## 9. 실행 전 무료 집합 진단

이미 본 DAY 684~690 구간은 새 모형 선택이나 성능 판정에 재사용하지 않고,
다음 집합 관계만 기술적으로 확인한다.

1. actual 후보가 맞히고 shuffle 후보가 놓친 정답쌍
2. shuffle 후보가 맞히고 actual 후보가 놓친 정답쌍
3. 1번 정답쌍 중 pooled 일반 후보에도 들어 있던 수
4. 1번 정답쌍 중 pooled 일반 후보 밖에 있던 수
5. 사용자·CLV 분위별 추가 후보 정답 포함 수

특히 기존의 `310-284=26`은 순증가일 뿐 actual-only 정답 26개라는 뜻이
아니다. 위 집합 분해로 유일한 양의 단서가 실제로 일반 후보 밖에서 생겼는지
먼저 확인한다.

일반 후보 밖 actual-only 정답이 없거나 actual의 추가 후보 정답 포함 수가
shuffle보다 많지 않으면 고비용 학습을 중단하고 M3를 종료한다.

## 10. 새 성능평가 구간 차단

다음 Dunnhumby 구간은 이미 결과를 본 상태다.

- DAY 684~690: 기존 M3 개발 진단에 사용
- DAY 691~697: 공통후보 M3 개발평가에 사용
- DAY 698~704: 이전 연구의 최종 test에 사용

DAY 705~711은 현재까지 열지 않은 구간이며, 기존 연구문서에서 사용 금지로
관리하고 있다. 따라서 구현은 가능하지만 **사용자·교수님의 평가 프로토콜
변경 승인 없이 이 구간의 정답·지표·결과파일을 만들지 않는다.** 새 M3의
성과평가는 승인된 새 사전고정 구간 또는 독립 데이터에서만 수행한다.

코드는 평가 경계와 명시적 실행 승인이 없으면 학습·평가를 시작하지 않도록
차단한다. 이미 본 구간에서는 9절의 후보 집합 진단만 허용한다.

## 11. 사전 판정 규칙

성과평가가 가능한 새 구간이 승인되면 다음 규칙을 실행 전에 고정한다.

주 판정은 실제 CLV arm의 Recall/NDCG@10·20·50 여섯 지표 기하평균이
다음 세 기준을 모두 초과하는지 확인하는 것이다.

1. M1 대비 `>1`
2. 일반 관계 대조군 대비 `>1`
3. degree-matched CLV shuffle 대비 `>1`

기계적 귀속 확인으로 actual 추가 후보의 신규상품 정답 포함 수가 shuffle보다
많아야 한다. 가격·구매금액 가중 적중값, 추천 상품 평균 가격 백분위, 노출
분포, CLV 분위별 결과는 모두 함께 보고하지만 사후 방어조건으로 추가하지
않는다. 단일 seed 결과에서는 유의성이나 일반화를 주장하지 않는다.

## 12. 필수 불변조건과 최소 테스트

실행 전 다음을 자동검사한다.

1. train pair가 모든 보조 후보에서 0개
2. 각 활성 사용자의 `S_G`, `E_a` 내부 중복 0개
3. `S_G`와 `E_a`의 교집합 0개
4. arm 2~4의 활성 사용자와 행당 엣지 수가 동일
5. arm 2~4의 기본 100개 엣지와 가중치가 정확히 동일
6. 각 행의 기본 블록 질량 `5/6`, 추가 블록 질량 `1/6`, 총질량 `1`
7. actual과 shuffle에서 CLV 값·추가 엣지가 실제로 달라짐
8. shuffle 전후 CLV 평균 절대변화량과 degree 구간별 상관 저장
9. `gamma=0`이면 세 보조 arm의 점수와 M1 점수가 정확히 동일
10. final test 외 holdout 미구성

작은 합성자료 단위테스트에서는 후보 제외, 결정적 tie-break, 100+20 엣지,
블록 질량, 실제/shuffle 분리, 부족 후보 fail-closed를 검증한다.

## 13. 구현 범위와 중단점

구현은 기존 후보관계 M3 모듈을 확장하고 다음을 제공한다.

- 위 세 보조 관계를 만드는 그래프 구성 함수
- 이미 본 구간에서 학습 없이 실행하는 집합 진단
- 새 평가구간을 임의로 열지 못하게 하는 설정 검증
- 단일 seed notebook과 결과 메타데이터 형식
- 관련 국소 단위테스트

논문 본문에서는 별도의 새 방법명을 만들지 않고 “일반 관계 밖 CLV 추가
후보 엣지”와 수식으로 서술한다.

집합 진단이 음성이면 학습 코드를 실행하지 않고 M3 구조 탐색을 종료한다.
집합 진단이 양성이고 승인된 새 평가구간의 단일 seed에서 주 판정을 통과하면
그때만 여러 seed와 독립 데이터로 확장한다.
